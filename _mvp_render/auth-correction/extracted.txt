P0: 多智能体协同开发系统搭建方案
P1: 首期 MVP 方案 | OpenCode + WSL2
P2: 版本：MVP 1.4（模型策略 A 已确认；GPT 订阅认证已澄清）    日期：2026-10-11    目标：在授权代码仓库验证六阶段交付闭环
P3: 1. 决策摘要
P4: 首期以 OpenCode 作为交互和 Agent 宿主，在 WSL2 Ubuntu 环境运行。流程决策由独立状态机负责，所有模型和工具访问经权限网关；OpenCode Skill 仅提供阶段模板、输入格式和退出清单。DSH 不进入首期，待 MVP 稳定后再评估迁移。
P5: 首期只支持 spec → plan → build → test → review → ship。A 已确认：DeepSeek 第三方公共 API 用于 build，接受供应商服务端实际路由（包括 V4.1 Flash），记录响应标识；客户端不自动切模。GPT-6.1 Sol 负责规划、架构和只读终审。失败保留现场，不自动修复、不自动全盘回滚。
P6: DeepSeek 官方资料对 V4 Pro 路由/继续提供服务存在冲突：9 月 10 日公告称 deepseek-v4-pro 请求会路由至 V4.1-Flash；更新日志及当前价格表又称继续提供 V4 Pro API、列出 V4-Pro-0813。[7][8] 用户已选 A，接受供应商服务端路由；M0 仍记录请求 ID、response.model、token、状态码、耗时和账单。若 response.model 只是请求别名回显，标记“底层版本未验证”，不将其误报为真实权重证明。
P7: 2. MVP 范围
P9: 模型策略拍板后，按角色固定请求模型 ID；关闭客户端自动路由、自动降级和跨模型重试。A 可接受供应商服务端路由。OpenCode Agent 只能通过 MCP 权限网关使用文件、终端、Git 和 Playwright；显式关闭绕过网关的直接文件写入与 Shell。[2]
P10: 模型策略拍板项（用户已确认 A）
P11: A｜接受 DeepSeek 公共 API 路由。质量：按实测返回的 V4 Pro/Flash评估，官方宣传与本项目编码结果不等价；成本：若按 Flash 计费有望最低，最终看供应商账单；难度：低，优先复用现有 Provider 配置思路；风险：服务端映射、质量和计费不透明；进度：三案中最快。接受 Flash 即继续，记录响应标识，不自动切换。
P12: B｜首期编码全部用 GPT-6.1 Sol。质量：固定单一型号便于建立基线，实际编码质量仍需试点验证；成本：预计高于按 Flash 计费的 A，供应商报价为准；难度：低至中，新增隔离的 GPT 编码 Worker/凭据并经网关授予受限写权限；风险：调整“GPT 只读”原规则，且仍需验证供应商模型映射；进度：接入通过后较可预测。规划/终审 Worker 仍只读。
P13: C｜改用 Kimi K3 编码。质量：官方定位包含长程编码/软件工程，但本仓库效果未知；成本：按第三方报价核算，不能以官方直连价代替；难度：中，须完成独立映射、凭据、工具兼容与任务验收；风险：模型映射和质量尚无本项目数据；进度：通常慢于 A/B，M0/M3 需多一轮验证。[9]
P14: 决策结果：首期执行 A，不同时接入 B/C。其主要优势是改动和成本预期较小；质量由 10 个试点任务验证。若 M3 未达到交付成功门槛，阶段失败阻断并提交人工决策，不自动切换 GPT 或 Kimi。30% 降本仍是待验证假设。
P15: 3. 运行结构与权限边界
P17: 角色权限：规划/评审可读源代码与测试证据，但不能写代码、执行任意 Shell 或提交；编码 Agent 仅可读写任务 worktree、执行白名单命令和查看 Git 状态/差异，禁止 push；测试工具只运行计划中批准的命令；ship 阶段由用户批准，网关使用短时授权执行 push。
P18: 每次模型或工具调用记录任务 ID、Agent/角色、请求模型 ID、供应商实际返回标识、token 用量、耗时、状态码及结果。供应商或订阅接口未暴露的字段标为“不可得”，不得用请求 ID 冒充实际返回模型。审计不记录完整提示、密钥或代码原文，参数先脱敏。第三方 API Key 按角色独立管理，DeepSeek 天翼 Key 仅供 build Worker 使用，不全局共享。GPT 规划/终审通过 OpenCode 官方 OpenAI Provider 的 ChatGPT 订阅登录授权（OpenCode 文档列出 Plus/Pro 登录），不是第三方 API，也不配置 OpenAI API Key；两个只读 GPT 角色可共用经授权的订阅会话，工具只读边界由外部状态机和 MCP 网关强制。订阅授权文件仅限 WSL2 服务用户访问且不入库。超时、限流按 Retry-After/退避规则处理，每阶段最多重试 2 次；鉴权失败（401/403）不重试。仍失败则阶段失败阻断，不自动换模型。网关故障或审计写入失败时拒绝写操作。
P19: 4. 六阶段流程与退出条件
P21: 状态机状态建议：待执行、运行中、待人工确认、通过、失败阻断、已取消。仅允许相邻阶段转换；失败后的重跑或退回 build 需要用户确认。服务重启后从 SQLite 恢复阶段与产物，不重复执行未确认的写操作。
P22: 5. Git、浏览器、模型与数据安全
P23: Git：开始任务前确认基线提交并创建独立 worktree/任务分支。MVP 禁止自动执行 git checkout -- .、reset --hard、clean -fd、自动全盘回滚和自动修复。失败时冻结任务、保留 worktree、diff 和日志；人工检查后仅处置本任务确认归属的文件。
P24: 浏览器：每任务独立临时 user-data-dir 或 Playwright isolated context；不连接个人浏览器 Profile。仅访问本地测试站点；通过最终 URL、指定 DOM、页面/控制台错误和网络失败状态判断，不以截图像素作为唯一通过条件。
P25: 模型策略：A 已确认，build 请求 DeepSeek 公共 API ID，接受供应商服务端路由（含 V4.1 Flash）；记录 response.model、usage、耗时和状态码。若 response.model 仅回显请求别名，标记“底层版本未验证”。客户端关闭自动路由、降级和切模；API 连续失败后阶段阻断。
P26: 数据边界：首期按任务将所需代码上下文发送至指定云端模型；GPT 规划/终审使用 OpenAI 官方 ChatGPT 订阅授权，DeepSeek build 使用天翼第三方 API。首期不实现敏感代码识别、屏蔽或外发审批。MCP 权限网关仍控制工具和写操作；第三方 API Key 按角色隔离，GPT 只读权限由网关执行；调用审计不记录密钥或完整提示内容。
P27: WSL2：仓库、Git worktree、Node/Python 运行时和 OpenCode 配置统一在 WSL2 Linux 文件系统。不要同时从 Windows 与 WSL2 修改同一个 worktree；固定 Node、OpenCode、MCP Server 版本并提交锁文件。OpenCode 官方将 WSL2 列为 Windows 推荐体验。[1]
P28: 6. 复用、自研与二期边界
P30: 状态机与 MCP 网关是首期自研核心。其余开源组件只提供底座能力，不代表阶段状态、权限策略、持久化或合规边界已经实现。状态机与工具契约独立于 OpenCode，便于二期评估 DSH，而不把流程规则写死在某个 Harness 中。
P31: 7. 实施顺序与交付件
P32: M0 前置核验（A 已确认）：GPT 侧确认 ChatGPT 订阅计划和账户可用，并按 OpenCode 官方 OpenAI Provider 流程使用 ChatGPT Plus/Pro 登录授权；此项不是 OpenAI API Key 连通性测试，不调用 api.openai.com API。GPT-6.1 Sol 是否出现在 OpenCode 模型列表、订阅额度及真实请求结果，安排在 M1 安装 OpenCode 后核验。DeepSeek build 侧用独立天翼 API Key 验证认证连通性；请求模型 ID、供应商实际返回标识、token 用量、耗时、状态码和账单逐项记录，A 接受实测返回 V4.1 Flash。若供应商只回显别名或某字段不暴露，明确标注“底层版本未验证”或“不可得”，不伪造信息。使用测试额度验证限流/超时、每阶段最多 2 次重试、401/403 不重试、失败阻断且不切模型。截图显示 ZCode 天翼 Provider 使用 https://ai.ctaigw.cn/v1、OpenAI Chat Completions，目录含 deepseek-v4-pro-0813、deepseek-v4-flash-vision-exp-0817、kimi-k3、glm-5.3、glm-5.3-flash；这只证明 ZCode 可选该目录，不证明 OpenCode 兼容、实际底层版本或账单。M0 完成环境/授权准备后进入 M1；M1 在 WSL2 OpenCode 中验证订阅登录、GPT-6.1 Sol 可用性和 DeepSeek 角色配置，成功后才进入 M2。另确认仓库及云端模型调用已获授权。
P33: M1 环境基线：完成前置核验后安装 WSL2 Ubuntu、OpenCode、Git、Node/Python 和 Playwright MCP；仓库放在 WSL2 内，固定依赖与最小权限配置。OpenCode 使用官方 OpenAI Provider 的 ChatGPT Plus/Pro 登录授权，核验 GPT-6.1 Sol 是否可选并做无副作用调用；DeepSeek 天翼 API Key 仅配置给 build Worker 并核验连通性。GPT 不配置 OpenAI API Key。未通过则暂停，不进入 M2。
P34: M2 控制与权限：实现 SQLite 状态机、阶段产物、审批入口、角色 Worker、MCP 网关、审计及模型标识记录/校验；先验证越权调用会被拒绝。
P35: M3 试点：在独立仓库运行 10 个小到中等任务，覆盖成功、测试失败、模型不可用、评审阻断、暂停恢复和浏览器校验。
P36: 交付件：可运行配置与锁文件、状态机/网关源码、权限矩阵、六阶段 Skill、任务日志样例、验收数据和未解决问题清单。
P37: 8. MVP 验收标准
P39: 匹配任务必须从相同基线提交创建隔离副本，使用同一验收标准和等价运行环境；失败、取消和人工补做成本单独记录。首轮 10 个任务只作为试点，不足以证明 30% 降本或长期成功率。
P40: 9. 已知阻断项与决策规则
P41: 模型身份与路由按已确认的 A 处理：供应商可将请求路由到 Flash，MVP 接受该行为并记录供应商响应与账单；API response.model 若是别名回显，标记底层版本未验证，不因此自动阻断或切模型。若 API 没有响应模型标识、token 用量、状态码等必要审计字段，M0 不通过；任何 API 故障均阶段失败阻断。
P42: 首期不设置敏感代码外发限制，所需代码上下文按角色发送至云端模型服务：GPT 规划/终审经 OpenAI 官方 ChatGPT 订阅授权，DeepSeek build 经天翼第三方 API。工具权限、DeepSeek build Key 隔离和脱敏调用审计照常执行。
