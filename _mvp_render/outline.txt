P0: 多智能体协同开发系统搭建方案
P1: 首期 MVP 方案 | OpenCode + WSL2
P2: 版本：MVP 1.1    日期：2026-10-11    目标：在授权代码仓库验证六阶段交付闭环
P3: 1. 决策摘要
P4: 首期以 OpenCode 作为交互和 Agent 宿主，在 WSL2 Ubuntu 环境运行。流程决策由独立状态机负责，所有模型和工具访问经权限网关；OpenCode Skill 仅提供阶段模板、输入格式和退出清单。DSH 不进入首期，待 MVP 稳定后再评估迁移。
P5: 首期只支持 spec → plan → build → test → review → ship。GPT-6.1 Sol 负责规划、架构和只读终审；DeepSeek V4 Pro 仅负责编码。测试由确定性命令与 Playwright 执行。失败时保留任务现场，不自动修复、不自动全盘回滚。
P6: 重要前置条件：DeepSeek 官方公告当前说明，公共 API 对 deepseek-v4-pro 的请求在 V4.1-Pro 上线前会路由到 V4.1-Flash。若必须使用真实 V4 Pro，启动前必须取得能保证模型版本的独立端点；无法保证时阻止 build 阶段，不静默替换模型。[7]
P7: 2. MVP 范围
P9: 首期模型请求均固定角色和模型 ID；关闭自动模型选择、模型降级及跨模型重试。OpenCode 默认工具权限较宽，部署时必须显式拒绝直接文件修改和 Shell 工具，并只开放网关 MCP 工具。[2]
P10: 3. 运行结构与权限边界
P12: 角色权限：规划/评审可读源代码与测试证据，但不能写代码、执行任意 Shell 或提交；编码 Agent 仅可读写任务 worktree、执行白名单命令和查看 Git 状态/差异，禁止 push；测试工具只运行计划中批准的命令；ship 阶段由用户批准，网关使用短时授权执行 push。
P13: 每次工具调用记录任务 ID、Agent/角色、工具名、资源路径或命令摘要、时间、结果码和关联模型/用量。日志不保存源码正文、密钥或完整敏感参数；调用结果中的密钥模式必须脱敏。网关故障或审计写入失败时拒绝执行写操作。
P14: 4. 六阶段流程与退出条件
P16: 状态机状态建议：待执行、运行中、待人工确认、通过、失败阻断、已取消。仅允许相邻阶段转换；失败后的重跑或退回 build 需要用户确认。服务重启后从 SQLite 恢复阶段与产物，不重复执行未确认的写操作。
P17: 5. Git、浏览器、模型与数据安全
P18: Git：开始任务前确认基线提交并创建独立 worktree/任务分支。MVP 禁止自动执行 git checkout -- .、reset --hard、clean -fd、自动全盘回滚和自动修复。失败时冻结任务、保留 worktree、diff 和日志；人工检查后仅处置本任务确认归属的文件。
P19: 浏览器：每任务独立临时 user-data-dir 或 Playwright isolated context；不连接个人浏览器 Profile。仅访问本地测试站点；通过最终 URL、指定 DOM、页面/控制台错误和网络失败状态判断，不以截图像素作为唯一通过条件。
P20: 模型固定：OpenAI 使用 gpt-6.1-sol；DeepSeek 使用经端点验证的 V4 Pro 版本。记录请求模型 ID 与供应商返回的版本信息；无版本证据、限流、超时或鉴权失败时将任务置为失败阻断，不自动切换模型。
P21: 数据边界：首期按任务将所需代码上下文发送至指定外部模型，不实现敏感代码识别、屏蔽或外发审批。MCP 权限网关仍控制工具和写操作；每个 Agent 使用独立凭据，调用审计不记录密钥或完整提示内容。
P22: WSL2：仓库、Git worktree、Node/Python 运行时和 OpenCode 配置统一在 WSL2 Linux 文件系统。不要同时从 Windows 与 WSL2 修改同一个 worktree；固定 Node、OpenCode、MCP Server 版本并提交锁文件。OpenCode 官方将 WSL2 列为 Windows 推荐体验。[1]
P23: 6. 复用、自研与二期边界
P25: 状态机与 MCP 网关是首期自研核心。其余开源组件只提供底座能力，不代表阶段状态、权限策略、持久化或合规边界已经实现。状态机与工具契约独立于 OpenCode，便于二期评估 DSH，而不把流程规则写死在某个 Harness 中。
P26: 7. 实施顺序与交付件
P27: M0 前置核验：确认 GPT-6.1 Sol 的 OpenCode 接入方式；取得可证明实际 V4 Pro 的编码端点；确认试点仓库及模型调用已获授权。三项任一未通过，暂停模型编码接入。
P28: M1 环境基线：安装 WSL2 Ubuntu、OpenCode、Git、Node/Python 和 Playwright MCP；仓库放在 WSL2 内；固定依赖版本与最小权限配置。
P29: M2 控制与权限：实现 SQLite 状态机、阶段产物结构、审批入口、角色 Worker、MCP 网关、审计和模型版本核验；先验证越权调用会被拒绝。
P30: M3 试点：在独立仓库运行 10 个小到中等任务，覆盖成功、测试失败、模型不可用、评审阻断、暂停恢复和浏览器校验。
P31: 交付件：可运行配置与锁文件、状态机/网关源码、权限矩阵、六阶段 Skill、任务日志样例、验收数据和未解决问题清单。
P32: 8. MVP 验收标准
P34: 匹配任务必须从相同基线提交创建隔离副本，使用同一验收标准和等价运行环境；失败、取消和人工补做成本单独记录。首轮 10 个任务只作为试点，不足以证明 30% 降本或长期成功率。
P35: 9. 已知阻断项与决策规则
P36: DeepSeek V4 Pro 版本锁定是首期上线阻断项。DeepSeek 官方公告当前说明公共 API 的 deepseek-v4-pro 会路由至 V4.1-Flash，直至 V4.1-Pro 上线。[7] 首期不得把模型 ID 等同实际模型版本。若供应商不能提供固定版本端点及可审计的响应标识，状态机禁止进入 build；由项目负责人决定等待、采购独立托管端点或调整范围。
P37: 首期不设置敏感代码外发限制，按阶段和角色权限调用 GPT-6.1 Sol 与 DeepSeek V4 Pro。工具权限、独立凭据和调用审计照常执行。
