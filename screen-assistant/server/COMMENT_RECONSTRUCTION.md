# 评论还原模块（独立候选）

`reconstruct_comments(observations, previous=())` 输入同一会话内已经验证的评论观察。观察包含 `source`、`event_id`、真实 `observed_at_ms`、`content.text`、可选 `content.text_position`（屏幕左上原点归一化 `x/y/width/height`）、可选 `capture_batch_id` 和 `line_index`。有批次时按来源和批次分开；无批次时每条独立。调用方负责会话隔离、输入验证、批次完整性、排队和有效期；缺少时间不能用服务器接收时间冒充。

2026-10-31 补充：拟由集成调用方提供的 `capture_comment_count` 用于传输完整性门控，并非语义评论数量。**PR12 的基线和本模块没有实现该传输字段、能力协商或服务端门控**；相关实现由独立集成 PR 负责，其合并和部署状态需另行确认。模块不自行判定批次是否收齐；生产调用方应先按协议确认收到全部合法项，再调用本模块。`partial` 和 `ambiguous` 只描述语义边界，不能证明传输完成；旧 DTO 缺批次时仍仅作单条处理。

本模块不以 OCR confidence 推断语义角色。调用方须先把已收到的不可靠项计入传输收齐，然后显式提供 `batch_complete=True` 和 `quality_gaps`：每个不能供重建的项传 `{event_id, text_position}`，位置未知为 null；经检查无缺口传空列表。`observations` 应只包含可用于重建的项；若质量缺口事件误同时传入，模块按事件 ID 剔除，不使用其文字，仍按缺口位置阻止升级。位置未知阻止整批升级，邻近缺口阻止相应评论升级。默认 `batch_complete=False, quality_gaps=None` 不升级；缺 batch、多个 batch 或来源混合也不升级。调用方仍负责会话隔离、质量检查和真实时效，本参数只是调用方断言，模块不能验证传输收齐。旧 DTO 不可伪称新批次完整。

输出字典包括临时 `comment_id`、`source`、`nickname`、`text`、`consumption_level`、`fan_level`、`fan_group`、每字段 `field_status`/`field_sources`、`source_event_ids`、真实 `first_observed_at_ms`/`last_seen_at_ms`、`boundary_status`、`tracking_status`、归一化 `position`、`usability_reasons` 和未经分类的 `header_evidence`。临时 ID 由首项来源、事件 ID 和观察时间确定，同输入重复调用结果一致；调用方仍须按会话隔离，不得当跨会话全局身份。`field_status` 对五个业务字段使用 `usable/candidate/unknown`：`usable` 仅可按下述局部规则使用，`candidate` 是未确认候选，`unknown` 对应 null。`field_sources` 同五键，值为真实输入 event_id 数组。`boundary_status` 为 `locally_complete/partial/ambiguous`；只有正文同时为 `usable` 和 `locally_complete` 才可按调用方业务规则消费，昵称仅在自身为 `usable` 时使用。`header_evidence` 不得用作身份；它可能含昵称等原始文字，不应写入常规日志或默认发给模型。两个等级和团名保持未知，不由前导数字或人工真值补猜。

首版仅在完整批次及质量信息均经调用方明确提供、同一框内唯一分隔出非空正文及可用矩形、无紧邻未归属观察或质量缺口、无省略号或上缘裁断迹象时升级；拼接正文暂不升级。数字开头的头部昵称仍为 unknown，装饰符开头的昵称仍为 candidate，正文可单独升级。`usability_reasons` 为正文不升级的机器原因数组：`batch_or_quality_unverified`、`body_or_geometry_uncertain`、`visible_truncation`、`near_top_edge`、`quality_gap`、`unlocated_observation`、`nearby_unassigned`；空数组只表示局部规则通过。`field_reasons` 按五字段给出原因数组：正文沿用上述原因，昵称可为 `ambiguous_header`，未分类的等级和团名为 `not_classified`。上缘规则只识别坐标明显靠上的风险；无 ROI 边界时无法证明没有裁断、遮挡或 OCR 漏检。`usable` 不是平台原文、完整采集或真实身份的保证，右侧浮层和误分隔仍可能误判。

`tracking_status=continuous_candidate` 表示唯一头部、正文相似度、相近横向位置、上移和时间同时满足，且至少两个相同片段或两个相邻评论呈一致上移与顺序的连续观察候选，并沿用临时 ID；单条匹配没有邻近证据时为 `ambiguous_single`，不沿用 ID。它不是平台消息ID或真实用户ID，不证明同名同文不是新消息。调用方不可仅凭此状态或相同 `comment_id` 将其作为确定的独立人数，也不可据此宣称零重复/零误吞。`previous` 必须为同会话紧邻上一采集轮的输出；空轮、缺帧、遮挡、离屏后重发、不同人同名同文和多重匹配均无法确认，调用方须保守处理。关联保留原始事件ID与首次真实观察时间；不会因后续观察重置首次时间。

`fragments` 保存本轮用于序列比较的 OCR 文本及框，可能包含个人信息，应与 `header_evidence` 一样按原始观察处理，不写入普通日志或默认发给模型。

同排依据垂直重叠和水平方向的局部距离；左侧未分类片段不并入评论，保留独立观察，紧邻正文框时阻止正文升级；不能仅凭位置断定片段为徽章。上下有独立评论头且正文非空的其他评论及其已归属片段视为边界，不因行间距小而单独阻止升级；未归属片段不因被单独输出而自动获得此豁免。短续行仅形成部分候选，不覆盖任意跨行。Paddle [BoxSorter 固定源码](https://github.com/PaddlePaddle/PaddleOCR/blob/77ddbafccdee5020368c16c6960e6ff51e40b971/deploy/ppocr-android/ppocr-sdk/src/main/java/com/paddle/ocr/postprocess/BoxSorter.kt)提供阅读顺序启发，Python [difflib](https://docs.python.org/3/library/difflib.html)提供序列相似比较；这两者不提供角色解析或确定的屏幕消息身份。本模块不重新实现 OCR，不使用图标颜色、字符级框或未提供的平台 ID。

当前几何参数是仅经所列样例校准的工程值，不是用户业务阈值：同排至少覆盖较短框高的 45%，相邻横向间隔不超过两框较窄宽度的一半；续行最多四字符、纵向间隔不超过起始框高的一半且不能与另一个明确起始同排。跨帧仅比较10秒内相似度至少0.95的唯一候选，要求横向偏移≤0.05及共同上移偏差≤0.03（均为归一化屏幕坐标）。这些条件既可能漏掉真实续行/连续消息，也不能排除误并；应继续用实场样例验证而非视为通用真值。

## 既有素材初步对照

以25号既有 Paddle 原始框和人工真值为对照，本模块实际运行但没有重跑 OCR。结构图 `badge_structure_1`：昵称候选“紫菜蛋花汤”和正文候选“bless you”与人工标注一致；消费49、灯牌11、团名爱哄人全部未知，未把 `1` 补成11。A30 `高冷男神互动就摆` 的 `我的我的` 与左移续行 `我的` 合并为候选，右侧广告未并入；视频27/30 `打野不带节奏靠队/友` 两轮形成同一**连续候选**并保留首次时间；B15 两名不同昵称的同文未被合并。上述为样例对照，不证明自动角色/身份可靠。

对旧版本 d986e4b 扩测25号独立小集8帧的30条人工标注（以其原始 JSONL 的 Paddle 检测项、框和该报告逐条真值人工对照；标点/emoji差异按其口径忽略）：正文候选 **22正确、1部分/错误、7未知**；昵称候选 **12正确、0已识别错误、18未知**；消费等级 **0正确、0错误、30未知**；4条可判灯牌 **0正确、0错误、4未知**。团名在该30条无可评分真值，结构图的团名未知。统计仅针对这30条已标注目标，不包括目标外候选；存在截断上缘文字和无分隔符文本等额外候选，不能据此声称误报为零。A30“点点关注点点赞，亮个粉丝牌！”仅输出首行，作为部分/错误；B52三条无分隔符候选当时未知。局部跨行回归曾暴露数字徽章和下一人无冒号文本误并，现有针对性测试覆盖这两例；不证明其他版面不会误并。统计基于 ROI 局部归一化框，与完整屏幕坐标条件不同，需要进一步同源验收。

2026-10-31 对旧版本 e8c4513 的可用资格复测：以同一八帧原始 Paddle 框构造**仅供离线规则测试的合成批次**，假设没有已知质量缺口；这不是旧素材真实存在 `capture_batch_id/count` 的证据。30 条目标中，按忽略一般标点的正文精确值自动比较，18 条有唯一匹配，其中 **7 条标记 usable**；7 条没有精确匹配，另有 5 条正文重复而无法仅按正文唯一归属。八帧合计产生 18 个 usable 输出，其中有不在30条目标分母内的输出，不能声称全为正确或用它们计算准确率。上述结果不代表后续左侧片段修复后的覆盖数。人工对照的原候选正确/部分/未知计数见上一段，不能混同于 usable 统计。真实结构图的 `bless you` 在现有单例回归中为 usable，等级仍未知；A30 截断上缘的“对看的”因上缘风险被降级，未归属长续行和右侧浮层不能靠收齐证明完整。同文不同人未合并；多片段正文当前仍保守为候选。

这些计数不是泛化准确率或生产可用结论。模块未接现有接口；最终产品链路的批次完整性、质量缺口传递、采集覆盖、显示与业务筛选均需另行验证。字段来源只说明 OCR 输入，并不证明正文或昵称为平台真值。
